# nix-games

Дополнения к игровому провайдеру RoscomVPN для Mihomo (`classical`, `yaml`).
Рабочий URL остаётся прежним: `https://raw.githubusercontent.com/gerGunter/nix-games/main/nix-games.yaml`.

## Что публикуется

`nix-games.yaml` содержит только вручную выбранные процессы. Начальный пример
`MyGame.exe` удалён; Apex и Valorant уже покрываются RoscomVPN. Пока дополнений нет,
валидный пустой список — `payload: []`. Провайдер RoscomVPN должен оставаться подключённым.

## Источники и ограничения

- [Discord Detectable Applications](https://discord.com/api/v10/applications/detectable):
  JSON-массив приложений, `id`, `name`, `executables[].name`, `os: win32`,
  `is_launcher: false`. Проверено 6 ноября 2026 года: 25 176 приложений.
  Это каталог распознавания, а не гарантия того, что приложение является игрой.
  Endpoint не является стабильным контрактом публичного Discord developer API.
- [RoscomVPN games.yaml](https://raw.githubusercontent.com/roscomvpn/custom-category/release/mihomo/games.yaml):
  `payload` с `PROCESS-NAME` и `PROCESS-NAME-REGEX`. Проверяются оба типа,
  включая широкое выражение `(?i).*Win64-Shipping.*`. Go regexp использует RE2.
- Другие источники пока не подключены: для них нужен отдельный проверенный адаптер.

Точные имена сравниваются без учёта регистра. Пути Windows/Unix сводятся к имени
файла; в кандидаты идут только безопасные ASCII `.exe`. Пропускаются лаунчеры,
общие имена, известные системные процессы, обновляторы, античиты, браузеры,
вспомогательные процессы и имена, относящиеся к нескольким Discord application ID.
Консервативный фильтр может исключать настоящие игры и не гарантирует исключения
всех обычных приложений. Каждое оставшееся имя всё равно требует проверки.

При HTTP-ошибках, пустом источнике, изменении обязательных полей или неподдержанном
формате правил выполнение завершается ошибкой без записи результата. Нет запасного
пустого списка RoscomVPN. YAML-парсер намеренно поддерживает только проверенный
plain-scalar формат: новый синтаксис требует обновления и тестов, а не пропуска строк.
Загрузка ограничена 64 MiB и 60 секундами, редиректы запрещены; исходники не исполняются.

## Автоматические предложения

После ручного слияния установочного PR:

1. В Settings → Actions → General включите **Allow GitHub Actions to create and
   approve pull requests**. Workflow использует встроенный `GITHUB_TOKEN`, без PAT.
   Это настройка разрешения GitHub; сам workflow не одобряет и не сливает PR.
2. Запустите Actions → **Propose game candidates** → Run workflow (ветка `main`).
   Затем проверка идёт по понедельникам в 06:23 UTC (10:23 Самара).
3. Получите draft PR, изменяющий **только** `review/candidates.json`: до 100 имён,
   Discord ID, названия приложений, исходные пути, SHA-256 источников и счётчики
   исключений. Полное число кандидатов указано в `total_candidates`.
4. Проверьте кандидатов. Наличие открытого bot PR блокирует новые предложения,
   чтобы не перезаписывать ручные правки. Отклонённые имена добавляйте в
   `review/rejected.json` отдельным ручным коммитом. Одного закрытия PR недостаточно:
   без записи в rejected имена будут предложены снова.

Слияние PR с отчётом **не публикует процессы**. Автоматизация не пишет рабочий YAML,
не делает auto-merge и не отправляет коммиты в `main`. Запись через GitHub API
ограничена путём отчёта в новой ветке. Actions закреплены по commit SHA.
PR-проверки работают с read-only правами, без `pull_request_target`.
По текущей документации GitHub PR от `GITHUB_TOKEN` запускает PR-проверки в состоянии
ожидания ручного **Approve workflows to run**; генератор также запускает тесты перед
предложением. Если создание PR запрещено политикой организации,
исправьте разрешение репозитория; PAT для обхода политики не нужен.

## Ручное добавление проверенных процессов

Требуется Go 1.23+ (CI: 1.26.5), без сторонних зависимостей.

```sh
git switch main
git pull --ff-only
git switch -c review/selected-games
go test ./...
go run ./cmd/catalog
# Укажите реальные имена из отчёта, проверенные на установленной игре:
go run ./cmd/catalog -approve 'verified-process.exe,another-verified-process.exe'
git diff -- nix-games.yaml
go test ./...
git add nix-games.yaml
git commit -m 'Add manually verified game processes'
git push -u origin review/selected-games
gh pr create --base main --title 'Add verified game processes' --body 'Describe games and routing verification here.'
```

Имена в примере — заполнители, они не будут приняты без присутствия в актуальном
источнике. `-approve` заново загружает источники, применяет все фильтры и допускает
только текущих кандидатов; он лишь изменяет локальный YAML, не делает commit/push.
Не используйте команду для массового одобрения каталога. Проверьте название игры,
реальное имя запущенного процесса и соединения через нужную группу Mihomo.
Только ручное слияние этого отдельного PR обновит правила у клиентов.

Для принудительного ручного контроля включите защиту `main`/ruleset: запрет прямых
push, обязательный PR, проверки и запрет bypass для автоматики. Требование отдельного
reviewer имеет смысл, если в репозитории есть второй сопровождающий. Настройки защиты
не создаются workflow; без них администратор технически может менять `main` напрямую.

## Локальная проверка без сети

```sh
go test ./...
go vet ./...
go run ./cmd/catalog -discord-file /path/to/discord.json -roscom-file /path/to/games.yaml
```

Снимки не коммитятся целиком. Отчёт детерминирован для одинаковых входов; ограничение
100 касается только размера PR, дедупликация и ручное одобрение используют весь каталог.
Генератор не удаляет существующие одобренные правила при исчезновении игры из Discord:
такие изменения следует проверять отдельно.
